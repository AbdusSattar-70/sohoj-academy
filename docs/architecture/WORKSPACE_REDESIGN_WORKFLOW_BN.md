# সহজ একাডেমি: কাজের পেজ ও সম্পূর্ণ পরিচালনার ধাপ

## মূল নিয়ম

Sidebar-এর একটি option একটি স্পষ্ট কাজের জায়গা খুলবে। ওই পেজে সেই কাজের records, actions, prerequisites এবং পরবর্তী ধাপ থাকবে। Menu rename দিয়ে ভুল page content ঠিক করা যাবে না। এই নথি লক্ষ্য workflow; সব feature ইতিমধ্যে সম্পূর্ণ—এমন দাবি নয়। CRM-এর public design, font, colour বদলাবে না।

## পেজের মালিকানা

| বিভাগ | কী থাকবে | কী থাকবে না |
|---|---|---|
| ওয়েবসাইট পরিচালনা | Public content ও showcase প্রকাশের কাজ | Class/subject/year তৈরির form |
| আবেদন ও যোগাযোগ | Unverified enquiry, follow-up, verification | স্থায়ী enrollment-এর অযাচাইকৃত পরিবর্তন |
| Academic settings | Classes, groups, subjects, years, programme definitions, schools ও reusable lists | Website editorial copy |
| Offerings | Programme-এর year/branch/eligibility, subjects ও প্রকাশের প্রস্তুতি | Payment receipt তৈরি |
| Routine | Batch/subject/teacher/room/day/time পরিকল্পনা | Actual attendance গণনা |
| Dated class | নির্দিষ্ট দিনের attendance, actual teaching ও changes | পুরো routine পরিবর্তন |
| Admission case | Identity, placement, fees, referral, review, enrollment, collection/receipt | অপ্রয়োজনীয় Prospect তৈরি |
| My attendance | নিজের উপস্থিত দিন/সময় | মোট referral earnings-এর বিভ্রান্তিকর summary |
| Earnings | Earned, paid, remaining; salary ও referral আলাদা | অনুমানকে confirmed payment বলা |

## শূন্য থেকে উদাহরণ

Coaching-এর SSC A+ Preparation ২০২৭, Class 10 Science, Morning A, ১২ জন, রবি-মঙ্গল-বৃহস্পতি সকাল ৭–৯টা, মাসিক tuition ৩,০০০ টাকা।

১. Bootstrap admin academy/branch পরিচিতি নিশ্চিত করেন; School, Coaching অথবা Training-এর কাজের ক্ষেত্র নির্বাচন করেন। Server/database-এ একই scope কার্যকর হতে হবে।
২. Seed থেকে Class 10, Science, subjects, year ও programme যাচাই করেন। Missing list যোগ; ভুল edit; ভবিষ্যতে ব্যবহার না হলে inactive। Training-এ অপ্রয়োজনীয় school class বাধ্যতামূলক নয়।
৩. Offering তৈরি: programme, branch, eligible class/group, subjects, কার্যকর dates ও সাধারণ days। নামের default programme থেকে; custom title ঐচ্ছিক। Draft, fees readiness, public visibility, applications ও routine readiness আলাদা।
৪. Standard fees ও allowed discounts নির্ধারণ করেন। Issued invoice নীরবে বদলাবে না; invoice টাকা গ্রহণের প্রমাণ নয়।
৫. Batch তৈরি: offering, capacity, days/time। Teacher/room/subject session এখনও routine-এ নির্ধারিত হবে।
৬. Staff access request যাচাই করে existing person মিলিয়ে Teacher role দেন। এক ব্যক্তির identity ও Staff ID একবার; request নিজে permission দেয় না।
৭. Teacher-এর teaching subjects নির্বাচন; teacher ও room availability/capacity নির্ধারণ। Availability এবং আগে থেকে booked class আলাদা যাচাই।
৮. Routine তৈরি: Morning A, Physics, teacher, Room 1, রবিবার সকাল ৭–৮টা, কার্যকর dates। Qualification, resource/batch overlap, room capacity ও dates যাচাই। Conflict হলে input থাকবে।
৯. Saved routine row থেকে dated sessions generate। Holidays skip কারণসহ; একই range আবার generate করলে duplicate নয়। Teacher নিজের assigned sessions দেখেন।
১০. Public showcase এবং application intake প্রস্তুত হলে প্রকাশ করেন। Public applicants account ছাড়া form দেন। ভুল preference-ও unverified enquiry হিসেবে গ্রহণযোগ্য; verified placement আলাদা।
১১. Admission-এর তিন পথ: নতুন শিক্ষার্থী, enquiry থেকে, existing student-এর নতুন programme। Direct admission অপ্রয়োজনীয় CRM Prospect সৃষ্টি করবে না।
১২. একই case-এ student/guardian/address/school, offering/batch, referral, fee/discount, physical consent ও final review। Missing school/relationship inline যোগ ও নির্বাচন। অসম্পূর্ণ হলে Draft।
১৩. Final admission permanent Student ID, প্রযোজ্য enrollment ও initial invoice সৃষ্টি করে। টাকা না পেলে due। Payment requirement থাকলে আগে দেখায়।
১৪. একই case-এ actual payment record ও receipt print। Discount টাকা গ্রহণ নয়। Financial adjustment নিয়ন্ত্রিত history সহ।
১৫. Teacher dated session খুলে student attendance, actual start/end, topics ও homework জমা দেন; admin accept বা correction চান। Staff presence, teaching hours ও student attendance পৃথক।
১৬. Substitute/room change/reschedule/cancel/makeup নির্দিষ্ট session থেকে; conflicts পুনরায় যাচাই। অতীত অনুষ্ঠিত class অপরিবর্তিত।
১৭. Teacher routine অনুযায়ী Google Docs-এ questions/answers প্রস্তুত করে chapter/topic/page range ও link জমা দেন। Admin review করে academy final document link যুক্ত করেন। Draft/final আলাদা; admin আলাদা question task দেন না।
১৮. Batch/subject-এর একটি test; তার অধীনে প্রতিটি student-এর marks/absence। Individual retest পৃথক প্রয়োজন; একই batch test বারবার তৈরি নয়।
১৯. Period-based progress: approved results/attendance/homework/topics ও teacher comments। Missing তথ্যকে zero/absent নয়। Teacher submission → admin final review → official report/print।
২০. Finance: student dues/collections, eligible net tuition referral rewards, staff pay, running income/expenses ও profit। Advanced ledger/assets workflow operator-facing scope নয়।

## প্রতিটি action-এর আচরণ

Required labels দৃশ্যমান; hint কার্যকর; longer help tap/focus/hover-এ। Pending button, duplicate request protection, failed input retention, exact field errors, persistent success এবং safe return-to-case থাকতে হবে। ফল অনিশ্চিত হলে records দেখে retry। Permissions server/RPC-তে; hidden menu নিরাপত্তা নয়। বাংলা/ইংরেজি নির্বাচন অনুযায়ী copy। Print করলে business record তৈরি নয়।

## Central search

Header-এ central search; sidebar search নেই। Ctrl/Cmd+K ও mobile icon। Page/action results এবং সীমিত server-side record results আলাদা। Student/name/ID/mobile, application reference, staff/referrer, programme/batch/class ও invoice/receipt অনুযায়ী search। প্রতিটি query-তে permissions ও assigned/workspace scope; browser-এ সব records load নয়। Navigation search তৈরি হলেই record search সম্পূর্ণ হয়েছে বলা যাবে না।

## ১৪ ধাপের delivery checklist

প্রতিটি implementation/fix যাচাই → পৃথক commit।

1. এই workflow ও page ownership নথি।
2. Website/CRM ও academic settings বিভাজন।
3. Page-specific content, duplicate heading/action/destination audit।
4. খালি guidance/labels-এর actual rendering তদন্ত ও fix।
5. Header central search, sidebar search removal, bounded authorized record search।
6. Setup readiness ও recovery।
7. Staff qualification/availability → routine → sessions।
8. তিন ধরনের attendance ও session changes।
9. One-case admission → invoice → payment/receipt।
10. Inline missing choices।
11. Questions/tests/progress workflow।
12. Earnings ও সহজ financial operation।
13. Form, mobile, print consistency।
14. Actual authenticated role/workspace end-to-end acceptance।

শুধু isolated build/SSR checks দিয়ে live-browser/database acceptance সম্পূর্ণ দাবি করা যাবে না।
