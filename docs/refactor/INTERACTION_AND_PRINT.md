# Interaction, navigation ও print contract

## CRM visual preservation
Current public CRM/home/About/FAQ/journal visual components, fonts, typography, colours, spacing/layout preserved। Dynamic content/form changes use same component styling। Baseline screenshots before implementation, compare desktop/mobile; no unsolicited rebranding/theme change।
Operational text/class ranges dynamic from configured content rather than hardcoded contradictory claims।

## কম typing
Searchable select with recent/relevant choices; checkbox/radio predefined reasons; auto fee/title/context; “permanent address same as present”; context keeps division/programme।
Select/create permitted for school/college, area/locality, guardian relationship, referrer, subjects/programme types and authorized directories। Not for system status, arbitrary privilege, currency or posting action।
Search → similar records → create inline → save and auto-select। Parent input/focus preserved, errors field-linked। Duplicate normalization plus server uniqueness; no name-only person merge।
Adult programme hides mandatory school guardian fields। Empty optional numeric value stays null, not Number("")=0। English/Bangla one locale at a time; untranslated directory proper names allowed।

## Forms ও requests
One shared field/feedback/pending/edit-panel pattern। Explicit open/close, invalid input retained, success closes only own editor। Cancel with unsaved content has deliberate retain/discard behaviour।
Default short reasons selected, “Other” explains। Server action discriminated result includes field errors/request identity/recovery state। No raw SQL errors to ordinary operator; trace remains internal।
Paged records with search/status/date/division; sorting stable। Database aggregate counts independent of page। No fetch-all workspace for one admission। Optional referral/history panel failure should not blank unrelated academic page।
Return context preserves working record and query/filter. Inline primary operations; exceptional separate page has validated internal return target and returns after success। No global close-all events।

## Print
Black/white, readable hierarchy, clear student/guardian/office-use sections; amount in words and numeric BDT। Current two-page blank admission concept: details/choices first page; declarations/office financial record/signatures and detachable acknowledgement second page。 Letterhead-safe configurable header clearance, no duplicate branding header on ERP forms/invoices/receipts।
Capital-letter guidance/character boxes where helpful, enough address writing space, special locality, permanent-address same tick; optional student mobile/email; current active programme and subjects tick choices।
System Student ID/roll office-assigned only। Blank detached money acknowledgement filled manually is later recorded with unique paper reference; blank system PDF never pretends payment received。
Print documents distinguish application received, admission confirmed, invoice due and actual paid receipt। Print preview has back/return button hidden in print; receipt only after confirmed payment, request uncertainty blocks falsely claiming receipt।
Print, CRM and ERP intake share one field catalogue and programme requirements; office-only fields never public. Runtime validate printer A4 scale/margins; no digital consent upload.

## Activity
Full audit in Activity: time, actor name/role/ID, action, record, reason; useful search/filter/pagination। Related profile shows concise relevant business history and link to filtered Activity, not duplicate raw audit table। Request/correlation trace internal support tool; not user typing requirement।
